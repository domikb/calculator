# Реализация упрощенного научного калькулятора

Данный документ описывает модификации, внесенные для создания упрощенной версии Калькулятора Windows, ориентированной исключительно на Инженерный режим.

## Реализованные изменения

### 1. Инженерный режим по умолчанию
- Изменен `ApplicationViewModel.cs` для использования `ViewMode.Scientific` вместо `ViewMode.Standard` по умолчанию
- Обновлен `MainPage.xaml.cs` для запуска в Инженерном режиме
- Изменен резервный режим со Стандартного на Инженерный при обработке ошибок

### 2. Упрощение навигационного меню
- Изменен `NavCategory.cpp` для фильтрации всех режимов кроме Инженерного
- Обновлен `CreateMenuOptions()` для включения только группы Калькулятор (без Конвертеров)
- Скрыты режимы: Стандартный, Программист, Вычисление дат и все режимы Конвертера

### 3. Сохранение состояния "Поверх всех окон"
- Добавлено сохранение состояния режима "Поверх всех окон"
- Состояние сохраняется в `LocalSettings` при приостановке приложения
- Состояние восстанавливается при запуске приложения в `RestoreAlwaysOnTopState()`
- Существующая функциональность "Поверх всех окон" (кнопка-булавка) теперь сохраняется между сессиями

### 4. Горячая клавиша (Ctrl+Shift+C)
- Добавлен метод `RegisterQuickLaunchHotkey()` для регистрации горячей клавиши Ctrl+Shift+C
- Реализован обработчик `OnQuickLaunchHotkeyInvoked()` для горячей клавиши
- Добавлен метод `ToggleWindowVisibility()`

## Ограничения платформы UWP

Это приложение Universal Windows Platform (UWP), которое имеет некоторые врожденные ограничения:

### Глобальные горячие клавиши
**Ограничение**: Приложения UWP работают в изолированной среде и не могут регистрировать настоящие системные глобальные горячие клавиши, которые работают, когда приложение не в фокусе.

**Что мы можем сделать**: 
- Комбинация клавиш Ctrl+Shift+C работает, когда приложение Калькулятор в фокусе
- Клавиатурное сокращение может использоваться для операций с окном внутри приложения

**Что мы не можем сделать**:
- Зарегистрировать горячую клавишу на уровне Windows, которая работает, когда приложение свернуто или когда другие приложения в фокусе
- Для этого потребуется:
  - Конвертация в приложение Desktop Bridge (Centennial) с полными правами доступа
  - Реализация отдельного Win32 сервиса/фоновой задачи
  - Использование Windows App SDK (WinUI 3) вместо UWP

### Функциональность системного трея
**Ограничение**: Приложения UWP не могут создавать иконки в системном трее или сворачиваться в системный трей в традиционном понимании.

**Что мы можем сделать**:
- Правильно обрабатывать приостановку приложения для сохранения состояния
- Приложение может продолжать работать в фоновом режиме при свертывании в панель задач
- Состояние сохраняется при возобновлении работы приложения

**Что мы не можем сделать**:
- Создать иконку в системном трее
- Перехватить закрытие окна для предотвращения завершения приложения
- Действительно "спрятать" приложение с панели задач
- Для этого потребуется:
  - Desktop Bridge с полными правами доступа
  - Win32 API для системного трея (NotifyIcon)
  - Windows App SDK с функциями для рабочего стола

## Альтернативные решения для полной функциональности

Для реализации настоящих глобальных горячих клавиш и функциональности системного трея, рассмотрите:

1. **Windows App SDK (WinUI 3)**: Миграция на Windows App SDK, который обеспечивает лучшую интеграцию с рабочим столом при сохранении современного UI
2. **Desktop Bridge**: Упаковка как приложение Desktop Bridge с полным доступом к Win32 API
3. **Гибридный подход**: Сохранить UWP калькулятор, но добавить небольшое вспомогательное Win32 приложение для регистрации глобальных горячих клавиш и управления иконкой в трее

## Тестирование реализации

1. Запустите калькулятор - он должен открыться непосредственно в Инженерном режиме
2. В навигационном меню не должно появляться других режимов
3. Используйте кнопку-булавку в заголовке для включения режима "Поверх всех окон"
4. Закройте и перезапустите приложение - состояние "Поверх всех окон" должно сохраниться
5. Нажмите Ctrl+Shift+C, когда приложение в фокусе - это вызовет обработчик быстрого запуска

## Известные проблемы

1. Ctrl+Shift+C работает только когда приложение в фокусе (ограничение UWP)
2. Нет иконки в системном трее из-за ограничений песочницы UWP
3. Невозможно предотвратить закрытие окна для свертывания в трей (ограничение UWP)
